01 · The one line that splits the decision

Fifteen minutes

Almost every "where should this run?" argument resolves at one number. Lambda stops at 900 seconds and there is no way to raise it. Everything below the line is a packaging choice; everything above it is an infrastructure choice.

TRAP
The Glue default is the one that will bite somebody in this room. A job created today defaults to Glue 5.1, which means an 8-hour timeout — not the 48 hours in every older blog post. A backfill that used to squeak through at 10 hours now dies at 8.
STALE
AWS's own EMR Serverless "considerations" page still tells you to set executionTimeoutMinutes = 0 for no timeout. That has been rejected for BATCH jobs since EMR 7.11. When a doc page and an API reference disagree, the API reference wins.

Glue Python Shell sizing — two legal values, not a range

AWS CLIthe cheapest managed Python in AWS
# DPU must be exactly 0.0625 or 1. Nothing in between. Default 0.0625.
# Either way you get 20 GB of local disk.
aws glue create-job --name python-job-cli --role Glue_DefaultRole \
  --command '{"Name":"pythonshell","PythonVersion":"3.9",
              "ScriptLocation":"s3://amzn-s3-demo-bucket/scriptname.py"}' \
  --max-capacity 0.0625

# NOTE: --allocated-capacity cannot be used for Python shell jobs.
# Contrast: glueetl / gluestreaming take 2-100 DPU, default 10, no fractions.
03 · Choosing

Same script, six homes

Under 15 min · pure Python

Lambda

Zip or container image, terminates on completion, pay per millisecond. The right answer for glue-code, API handlers and S3-triggered small work.

Not for anything that might grow past 15 minutes — there is no escape hatch.

Any duration · pure Python

Glue Python Shell

0.0625 DPU is roughly 1/16 of a worker — the cheapest managed way to run a long Python script on AWS. 20 GB disk, no cluster, no container to build.

Ideal for the 2-hour script that is not distributed work.

Any duration · distributed

Glue Spark / EMR Serverless

When the work is actually a Spark job. EMR Serverless gives custom vCPU/RAM ratios and open-source Spark; Glue gives tighter catalog integration and job bookmarks.

Any duration · your own image

ECS Fargate / AWS Batch

Containerise and run. Batch adds queueing, retries, array jobs and automatic compute provisioning; Fargate is the plain "just run this container" option.

Batch has no timeout by default — good and dangerous.

Existing fleet

EC2 + SSM

No new infrastructure at all — the SSM Agent on machines you already run pulls and executes the script. Chapter 04.

Not compute

Amazon S3

S3 cannot execute anything. It is where the script lives and, often, what triggers it. Worth saying explicitly because it comes up.

04 · Code straight from S3

Five services that fetch and run a script for you

No image build, no redeploy: change the file in S3 and the next run picks it up. Each of these takes an S3 URI and does the download itself.

1 · AWS Glue — --scriptLocationper-run override of the job's script
aws glue start-job-run --job-name "CSV to CSV" \
  --arguments='--scriptLocation="s3://my_glue/libraries/test_lib.py"'
2 · EMR on EC2 — script-runner.jarthe path changed in EMR 7.13
# EMR 7.13+ : the jar is ON THE AMI. No URI needed.
aws emr add-steps --cluster-id j-2AXXXXXXGAPLF \
  --steps Type=CUSTOM_JAR,Name="Run a script",ActionOnFailure=CONTINUE,\
Jar=script-runner.jar,Args=[s3://amzn-s3-demo-bucket/my-script.sh]

# EMR 7.12 and lower : full S3 URI, region as a PREFIX on the bucket
aws emr add-steps --cluster-id j-2AXXXXXXGAPLF \
  --steps Type=CUSTOM_JAR,Name="Run a script",ActionOnFailure=CONTINUE,\
Jar=s3://us-west-2.elasticmapreduce/libs/script-runner/script-runner.jar,\
Args=[s3://amzn-s3-demo-bucket/my-script.sh]

# Args must be comma separated with NO whitespace between elements.
3 · EMR Serverless — entryPointrequired field, max 4096 chars
aws emr-serverless start-job-run --application-id <id> --execution-role-arn <arn> \
  --job-driver '{"sparkSubmit":{"entryPoint":"s3://bucket/app.py",
                  "entryPointArguments":["--date","2026-09-02"],
                  "sparkSubmitParameters":"--conf spark.executor.cores=4"}}'
4 · Systems Manager — AWS-RunRemoteScriptruns on EC2 / on-prem via the SSM Agent
aws ssm send-command \
    --document-name "AWS-RunRemoteScript" \
    --output-s3-bucket-name "amzn-s3-demo-bucket" \
    --output-s3-key-prefix "key-prefix" \
    --targets "Key=InstanceIds,Values=instance-id" \
    --parameters '{"sourceType":["S3"],
                   "sourceInfo":["{\"path\":\"https://s3.aws-api-domain/script-path\"}"],
                   "commandLine":["script-name and arguments"]}'

# THE #1 MISTAKE: sourceInfo is a JSON STRING inside a LIST, escaped.
# Use the https:// virtual-hosted URL form — that is what the normative
# plugin reference uses. Instance profile needs s3:GetObject + s3:ListBucket.
5 · SageMaker Processingthe script is just another input
# code="s3://..." is Python SDK sugar. The API models the script as an input.
app_specification={
    "image_uri": 'image_uri',
    "container_entrypoint": ["python3", "/opt/ml/processing/input/code/preprocessing.py"]},
processing_inputs=[
    {"input_name": "code",
     "s3_input": {"s3_uri": 's3://path/to/preprocessing.py',
                  "local_path": "/opt/ml/processing/input/code",
                  "s3_data_type": "S3Prefix", "s3_input_mode": "File"}}]

# The MANDATED rule is only the prefix: every path must begin with
# /opt/ml/processing/ . The .../input/code/ location is convention.
6TH
There is a sixth, image-free option worth knowing: a generic container whose command is aws s3 cp s3://bucket/script.py . && python script.py. You then change behaviour by editing the S3 object instead of building and pushing a new ECR tag. Works on Batch, ECS and EKS alike.
05 · Triggers

What starts the thing

Three families: time, event, and orchestration. The distinction that catches people is between EventBridge Rules and EventBridge Scheduler — they target different things.

06 · The correction that saves you a function

You probably don't need the Lambda shim

The pattern everybody writes down is S3 → Lambda → ecs.run_task / glue.start_job_run. It works, and for a 5-minute job Lambda can just be the compute. But when Lambda exists only to call another API, EventBridge removes it entirely.

GLUE
A Glue workflow start trigger accepts three types: schedule, on-demand, or EVENT. The EVENT type takes a batch size and batch window, so you can accumulate N files or wait M seconds before firing — which is usually what you actually want when files arrive in a trickle.
07 · Verification log

Seven claims checked. Four were wrong.

Claim as commonly statedStatusWhat the docs say
Lambda caps at 15 minutesVERIFIED900 seconds, plus all the memory and package limits in chapter 02.
Glue job timeout is "48–168 hours"WRONG FRAMING168 h is a hard max, not a default. Defaults split by Glue version: 48 h for ≤4.0, 8 h for 5.0+. New jobs default to 5.1.
Glue Python Shell goes "as low as 0.0625 DPU"VERIFIEDAnd it is not a range — the only legal values are 0.0625 or 1. Both give 20 GB local disk.
ECS Fargate has no runtime limitNUANCEDNo documented maximum, but task retirement stops long-running tasks. The retirement wait setting is 0/7/14 days — plan for ~14.
EMR Serverless: set timeout 0 for no limitNO LONGERRejected for BATCH since EMR 7.11; max is now 7 days. Still valid for STREAMING. AWS's own considerations page is stale.
EMR script-runner.jar lives at a per-region S3 pathOUTDATEDTrue for EMR ≤ 7.12. On 7.13+ it ships on the AMI — pass bare script-runner.jar. Bucket form is <region>.elasticmapreduce.
EventBridge can trigger a Glue jobHALFRules target a Glue workflow. To call StartJobRun directly you need Scheduler's universal target.
S3 → Lambda → ECS/Glue is requiredNOT REQUIREDS3 → EventBridge → ECS task / Batch queue / Glue workflow needs no Lambda at all.
SageMaker script lands in /opt/ml/processing/input/IMPRECISEThe mandated rule is only that paths begin with /opt/ml/processing/. The script convention is /opt/ml/processing/input/code/.
EKS Jobs have an AWS runtime limitNOT AWSNo AWS-documented limit. activeDeadlineSeconds is upstream Kubernetes — do not cite an AWS URL for it.
AWS Batch has a default timeoutFALSE"By default, AWS Batch doesn't have a job timeout… There's no maximum timeout value." A hung job runs forever unless you set one.
RULE
Two lessons that generalise beyond this page. First: when a default changes with a service version, every blog post written before that version is now wrong — the Glue 48 h → 8 h shift is a live example. Second: when a user-guide page and an API reference disagree, the API reference wins; that is what caught the EMR Serverless timeout change.
